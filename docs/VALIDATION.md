# 验证与试点

本项目的自动化测试验证业务规则及受控生成的答题卡，不代表真实手写卷识别准确率。

## 已提供的自动化验证

```powershell
.venv/Scripts/python backend/manage.py test core.tests
cd frontend
pnpm run build
```

- 邮箱验证、密码重置、登录CSRF。
- 教师列表、对象、关联外键及私有文件隔离。
- 未审核参考答案不能发布；作答识别未确认不能定分。
- 发布后版本冻结；改分更新错题并保存历史。
- 学生手写答案与独立AI答案分开；随卷答案页按题号匹配。
- 重复任务不重复建题，重复归档不重复建作答。
- 外部试卷复用于不同学生；不同题干版本阻止误关联。
- 原题复练关联原作答；新作答不覆盖旧错误。
- 答题卡PDF渲染后识别：空涂、填B、错学生、定位点缺失、90/180/270度旋转。
- AI格式验证、保守数值比较、超时恢复和修订副本。

## 真实资料验收（需要教师提供并标注）

至少200页：规范答题卡100页、普通资料100页；普通资料包含空白卷、附答案卷、学生手写卷、零散错题。按学生和试卷来源划分验证集，避免同一套卷同时用于调参和验收。

每题标注题号、题干与图形是否完整、所有页面区域、参考答案、学生真实作答、教师评分和处理耗时。包含双栏、跨页、公共题干、缺图、阴影、涂改、遮挡、缺页和版本冲突。

使用 `scripts/evaluate.py` 对齐人工标注和预测结果：

```powershell
.venv/Scripts/python scripts/evaluate.py docs/validation-gold.example.jsonl docs/validation-predicted.example.jsonl
```

示例文件只有合成的格式样例，不能作为真实准确率报告。真实数据另存，不提交Git。

每行代表一份资料，`id`对应相同样本，`questions`按唯一题号关联。`regions.page`为样本内页号，`bbox`为归一化坐标。`answer`用于识别文字的严格对比（不作数学等价判定）；`score`为教师/系统分数；`auto_finalized`表示是否未经教师逐题定分；`manual_seconds`为实测耗时。

报告分别输出召回率、完整裁切率（所有人工区域都需有IoU≥0.85匹配）、匹配题答案准确率、评分差异、自动覆盖率及人工耗时。多余切题、图形完整性、题干/手写混淆、错学生/错卷还须单独人工检查，不能仅凭IoU验收。

**上线门槛：**错学生、错试卷的结果不能自动发布；低置信度与未确认答案不得自动归错；只有完成真实样本验证的题型/模板才能启用自动定分。默认 `AUTO_GRADING_ENABLED=0`。

## 运维验证

Docker环境需实际验证PostgreSQL迁移、RabbitMQ任务重试、worker终止后恢复、私有S3读写和备份恢复。没有运行这些服务时，不将配置存在视作部署验证完成。
